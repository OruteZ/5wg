# Progression

성장 축의 기획 — 경험치, 레벨업, 카드 선택. 무기 자체는 `weapons.md`에 있다.

이 문서는 문답으로 확정한 내용만 담는다. **"미정"으로 적힌 것은 아직 결정되지 않은 것이지
생략된 것이 아니다** — 채우지 말고 물어야 한다.

## 한 줄 요약

**레벨업의 쾌감과 음악의 쾌감이 같은 순간에 와야 한다.** 그래서 경험치도 레벨업도 박에 맞고,
카드가 떠도 음악은 끊기지 않는다.

## 경험치 — 음표

경험치 재화는 **음표**라 부른다. 종류에 따라 값과 출현율이 다르다. 적이 죽을 때 아래 확률로 나온다.

| 종류 | 값 | 출현율 | 비고 |
| --- | --- | --- | --- |
| 16분음표 | 1 | 기본 | 아래 세 종류가 안 나오면 이것이 나온다 |
| 4분음표 | 15 | 4% | |
| 온음표 | 100 | 0.3% | |
| 도돌이표 | 800 | 0.05% | 한 번에 여러 레벨이 오른다. 8분 이후부터 출현 |

출현율을 반영한 마리당 평균 획득량은 약 **2.3**(정확히는 2.26)이다. 아래 "필요 음표 테이블"은
이 배율을 반영한 값이다.

> 이전에는 "적 1마리 = 경험치 1"인 균일 지급이었다. 지금은 4종류 확률 지급으로 바뀌었다 —
> 아래 레벨업 페이스 전체가 이 변경을 전제로 다시 짜였다.

## 레벨업 페이스

| 항목 | 값 |
| --- | --- |
| 한 판 | 4회차(곡 4회 재생) / 15분 기준 |
| 목표 총 레벨업 횟수 | **45회.** 레벨 상한은 없다 |
| 곡별(회차별) 레벨업 배분 | 1곡 18회 / 2곡 15회 / 3곡 11회 / 4회차(보스) 1회 |
| 45레벨 도달 시점 | 12분(보스 등장). 성장은 여기서 끝난다 |
| 한 판 총 처치 수 | 약 6,100마리 |

### 필요 음표 테이블

적 1마리당 평균 획득 2.26 기준. 스폰율에서 나오는 누적 처치 수에 음표 종류별 출현율을 곱해
역산한 값이다.

| 레벨 구간 | 레벨당 필요 음표 | 구간 누적 | 도달 시점 |
| --- | --- | --- | --- |
| Lv1-19 | 59 | 1,062 | 4분 |
| Lv19-34 | 134 | 3,072 | 8분 |
| Lv34-45 | 561 | 9,243 | 12분 |

> 이전 문서는 요구 경험치를 `5 + 3 × (레벨 - 1)`인 **선형 곡선**으로, 목표를 40회로 적었고
> 이미 코드로도 그렇게 구현돼 있다(`architecture.md`). 지금 기획은 이 값을 완전히 대체한다 —
> 위 구간별 테이블이 새 기준이고, 구현이 여기 맞춰 갈아엎어야 한다는 사실은 `progress.md`의
> 미해결 목록에 남겨둔다.

### 강화 칸이 모자란 것은 의도다

한 판의 강화 칸은 6슬롯 × 5레벨 = **30개**인데 카드는 **45회** 뜬다.
30칸이 다 차면 남은 약 15회는 고를 무기 강화가 없다. 그 회차는 소모성 보상 구간이다.

## 상자

- **드랍**: 엘리트 처치 시. 곡당 1마리(3분 / 7분 / 11분), 한 판에 **3개.** 보스 곡에는 없다.
- **효과**: 보유 중인 무기·패시브 중 **1개에서 5개가 무작위로 강화된다.** 선택지 없이 즉시 적용된다.
- **개수별 확률**: 1개 10% / 2개 25% / 3개 30% / 4개 25% / 5개 10% (평균 3개).
- 진화와의 관계: **미정.**

한 판 총 상자 강화 횟수는 약 **9회**(엘리트 3마리 × 평균 3개)다. 레벨업 45회 + 상자 9회 +
상점 구매 7회 = **총 성장 61회**가 한 판의 성장 총량이다(→ `weapons.md`의 무기 성장, 스탯 곡선은
DPS를 시작 대비 약 50배로 키우는 것을 목표로 잡는다: `r = 50^(1/61) ≈ 1.0662`, 성장 1회당 약 +6.6%).

**성장은 12분에 끝난다.** 45레벨 도달, 상자, 상점이 모두 12분까지다. 보스는 DPS 500으로 상대한다.
45레벨 이후 레벨업의 처리는 **미정**이다.

## 카드 선택

### 형태

- 레벨업 **1회 = 카드 3장 중 택1**(현재 구현 기준).
- 레벨업은 **상시** 발생한다. 곡 경계로 몰지 않는다 — 선택 UI가 뜨는 지점이 곡 구조의 저강도
  구간(Break 등)에 몰리도록 스폰·경험치 곡선을 설계한다. 곡 내부 Break 구간은 적이 줄어드는
  자리가 아니라 레벨업 UI가 뜨는 자리로만 쓴다.

### 후보 구성 규칙 — 기획은 아직 미정이다

**아래 항목은 노션 기획 DB에 전부 `[ ]`(미정)으로 남아 있다.** 현재 구현(`LevelUpDraft`)은
문답으로 정했던 규칙을 이미 코드로 갖고 있지만, 그 규칙이 정식 기획으로 확정된 것은 아니다.
구현 쪽 실제 동작은 `architecture.md`의 "성장" 절과 `progress.md`를 본다.

| 규칙 | 상태 |
| --- | --- |
| 한 번에 뜨는 선택지 수 | 미정 |
| 무기 / 패시브 / 기타 등장 비율 | 미정 |
| 신규 획득 대 기존 강화 비율 | 미정 |
| 슬롯 만석 시 신규 무기 등장 여부 | 미정 |
| 만렙 항목 등장 여부 | 미정 |
| 같은 선택지가 중복해서 뜨는가 | 미정 |
| 특정 무기의 등장 가중치를 조절하는가 | 미정 |
| 선택지가 고갈됐을 때의 처리 | 미정 |

### 조작 — 아무것도 멈추지 않는다

**카드가 떠 있어도 게임은 계속 돈다.** 음악도, 적도, 발사도.

| 항목 | 규칙 |
| --- | --- |
| 입력 | 마우스 클릭 + 숫자키 1·2·3 |
| 위치 | 화면 중앙 하단 |
| 고르지 않으면 | 무한 대기. 그동안 경험치는 계속 쌓인다 |
| 대기 중 또 레벨업하면 | 큐로 쌓아 순서대로 소진 |

시간을 멈추지 않는 이유는 **음악을 끊지 않기 위해서**다. `Time.timeScale`은 애초에 쓸 수 없다 —
`BpmClock`이 `AudioSettings.dspTime` 기준이라 timeScale로는 박이 멈추지 않고 화면과 어긋나기만 한다.

### 리롤 / 스킵 / 밴

- 리롤은 필드에서 얻는 아이템 자원으로 쓴다(→ `pickup.md`). 레벨업 카드와 상점 양쪽에서
  재추첨에 쓸 수 있다.
- 스킵 가능 여부와 보상: **미정.**
- 밴 기능 여부: **미정.**

## 박자 동기화

경험치 흐름 전체가 박에 맞는다. 이게 레벨업을 음악적 사건으로 만든다.

- **오브 흡수** — 오브가 수집 범위에 들어온 순간 곧바로 빨려오지 않는다.
  **가장 가까운 다음 정박에 플레이어에게 도착하도록** 이동 속도를 맞춘다.
  여러 오브가 한 박에 함께 도착하면 소리도 한 번에 나서 그 자체로 리듬이 된다.
- **너무 촉박하면 한 박 미룬다** — 다음 박까지 남은 시간이 한 박의 30% 미만이면
  그다음 박을 목표로 잡는다. 순간이동처럼 보이는 것을 막는다.
- **정박 기준.** 서브박(8분·16분)까지 허용하면 사실상 아무 때나 들어와
  "박에 맞춰 들어온다"는 감각이 사라진다.
- **레벨업 시점** — 경험치가 들어오는 순간이 이미 박이므로 레벨업도 자연히 박에 맞는다.
  별도 지연을 두지 않는다.

120BPM 기준 최대 지연은 0.5초이고, 오브가 날아오는 시간이 그 지연을 시각적으로 채운다.

## 영구 강화와의 접점

런 사이 메타 상점(영구 강화 구매)이 있다. **상점 설계는 아직 문서가 없다** — 착수할 때
`shop.md`로 뺀다. 이 문서에는 무기 스탯과의 합산 계약만 남긴다.

적용 순서는 이렇게 고정한다.

```
무기 레벨 표(절대값) → 그 판의 카드 강화 → 영구 강화
```

영구 강화는 **합연산**이다. 레벨 표 값에 그대로 더한다.

> 참고: 레벨 표가 절대값이라 합연산을 섞으면 표만 보고 최종 수치를 알 수 없다.
> 곱연산이면 표가 항상 기준값으로 남는다는 이점이 있었으나, 합연산으로 결정됐다.
> 수치 튜닝 시 표와 실제 값이 벌어지는 것을 감안해야 한다.

## 구현 상태

카드 선택은 구현돼 있다 — `LevelUpDraft`(규칙) + `LevelUpOption`(적용) + `LevelUpCardView`(화면).
구조는 `architecture.md`의 "성장" 절.

| 항목 | 상태 |
| --- | --- |
| 3장 택1, 신규/강화 혼합, 빈 슬롯 가중, 중복 없음 | 됨 — 다만 이 규칙 자체가 기획 확정 사항은 아니다(위 "후보 구성 규칙" 참고) |
| 3장 못 채우면 남은 만큼 / 후보 0이면 힐 자동 적용 | 됨 (힐만. 화폐는 상점이 없다) |
| 아무것도 안 멈춤, 무한 대기, 큐 | 됨 |
| 마우스 클릭 + 숫자키 1·2·3 | 됨 |
| 경험치 곡선 `5 + 3 × (레벨-1)`, 목표 40회 | **됨 — 단, 위 "필요 음표 테이블"(45회 목표)로 대체될 예정** |
| 음표 4종 확률 지급 | **안 됨.** 지금은 적 1마리 = 경험치 1 |
| 상자(엘리트 드랍 강화) 시스템 | **안 됨.** 미구현 |
| **오브 흡수의 박자 동기화** | **안 됨.** 지금은 그냥 가속해서 끌려온다 |

## 미정

- **상점 설계 전반** — 무엇을 파는가, 화폐 획득량, 해금 구조, 세이브.
  착수 시 `shop.md` 신설(아직 없다). 판 안 화폐(티켓)는 `pickup.md`.
- **소모성 보상의 수치** — 힐량(임시 25), 화폐량, 후반 증가 곡선.
- **카드 UI 연출** — 등장 방식, 곡의 마디와 맞출지 여부. 지금은 uGUI 그레이박스다.
- **카드 후보 구성 규칙 전반** — 위 표 참고.
- **상자와 진화의 관계.**
- **패시브 아이템** — VS의 패시브 슬롯에 해당하는 축. 이번 범위 밖으로 뒀다.
  무기 축이 굳은 뒤에 슬롯·카드 풀·스탯 합산을 함께 설계한다.
