# Weapons

무기 축의 기획. 성장·업그레이드는 `progression.md`에 있다.

이 문서는 문답으로 확정한 내용만 담는다. **"미정"으로 적힌 것은 아직 결정되지 않은 것이지
생략된 것이 아니다** — 채우지 말고 물어야 한다.

## 한 줄 요약

**무기 하나가 악기 하나다.** 곡에서 그 악기가 연주되는 타이밍에 공격이 나간다.
무기를 고르는 것은 곡에 레이어를 얹는 행위고, 빌드가 완성될수록 곡이 두꺼워진다.
허전한 멜로디에 악기들을 쌓아가는 것이 이 게임의 핵심 경험이다 — 멜로디 라인만 항상 재생되고
나머지는 전부 무기다.

## 수치 정의 — 박당, BPM 정규화

모든 무기 수치는 **박당**으로 정의한다. 무기 표에 적는 데미지는 전부 **기준 데미지**(기준 BPM 100)다.
곡 BPM이 달라도 무기 DPS가 변하지 않도록 실제 발당 데미지를 정규화한다.

```
실제 발당 데미지 = 기준 데미지 × (100 / 곡 BPM)
DPS            = 기준 데미지 × 박당 발사 수 × (100 / 60)
```

- 곡 BPM 60이면 발당 데미지 1.67배, 120이면 0.83배가 된다. **발사 횟수와 소리 밀도만 BPM을 따라간다.**
- **BPM 허용 범위: 최저 60 / 최고 120.** 곡마다 다르게 잡는다.
- **발사 빈도는 16분 격자에 균등 배치되는 값만 쓴다: 0.25 / 0.5 / 1 / 2 / 4.**
- 격자 최소 단위는 16분(1박 = 4칸). 기본 박자표는 4/4이나 곡마다 다른 박자표를 쓸 수 있다.
  무기 패턴은 박자표별로 따로 만들지 않는다 — 박자표가 바뀌면 마디 길이와 칸 수만 달라진다.

## 코어 4종 + 스테이지 전용 6종

10종을 전부 스테이지마다 새로 만들지 않는다.

- **코어 4종**: 킥 / 베이스 / 기타 / 건반. **모든 스테이지에 공통.** 시작 시 이 중 하나를 고르고,
  나머지도 레벨업 선택지에 등장한다.
- **스테이지 전용 6종**: 스테이지마다 다른 악기. 범용성을 요구하지 않는다.
- **스테이지당 총 10종** 중 한 판에 **6개 슬롯**을 채운다. 10종 중 6종만 고를 수 있고,
  최대 5레벨이므로 한 판의 강화 칸은 6 × 5 = 30개다(→ `progression.md`).

## 스탯 축

무기별 고유 표가 아니라 **공통 스탯 세트**를 두고, 무기는 자기가 쓰는 필드만 채운다.
전역 강화("이동속도 +10%")를 한 곳에서 처리할 수 있고 카드 후보 풀도 단순해진다.

| 묶음 | 필드 |
| --- | --- |
| 위력 | 데미지 / 치명타 확률 / 치명타 배수 / 관통 수 |
| 범위 | 사거리 / 효과 반경 / 투사체 크기 / 지속시간 |
| 빈도 | 발사 수 / 연주 밀도 배수 / 쿨다운 감소 |
| 거동 | 투사체 속도 / 유도 강도 / 넉백 / 반사 횟수 |
| 생존·전역 | 이동속도 / 최대 체력 / 경험치 획득량 / 자석 반경 |

"생존·전역" 묶음은 무기가 아니라 플레이어에 붙는다. 카드 후보에는 들어가되
무기 강화와는 다른 경로로 적용한다.

`WeaponLevelData`에 15축이 전부 있고, 그중 **10축은 실제로 소비된다.**
남은 5축(치명타 확률·치명타 배수·연주 밀도·쿨다운 감소·반사 횟수)은 아직 선언만 돼 있다
(→ `architecture.md`의 "무기 스탯").

레벨 표는 인스펙터에서 무기마다 따로 만지는 것 말고 **TSV 왕복**으로도 편집한다.
`WeaponDefinition`의 버튼 두 개가 표를 클립보드로 복사하고 되받는다. 10종을 스프레드시트
한 화면에 놓고 밸런싱한 뒤 붙여넣는 흐름이다. 붙여넣을 때 헤더가 있으면 **열 이름으로** 맞추므로
스프레드시트에서 열 순서를 바꿔도 값이 엉뚱한 축에 들어가지 않는다.

## 슬롯

- 한 판에 **최대 6종**. 10종 중 6종만 고를 수 있다.
- **교체 불가.** 고른 것을 버릴 수 없다.
- 무기별 **최대 5레벨**. 즉 한 판의 강화 칸은 6 × 5 = 30개다.

## 무기 성장

- **강화 항목(가안)**: 데미지, 투사체 크기, 사거리, 관통, 넉백, 발사 수, 노트 추가.
  **강화 항목 전체 목록은 미정이다** — 위는 후보일 뿐 확정이 아니다.
- 무기별로 어느 레벨에 무엇이 오를지는 레벨 테이블에서 정한다(무기 수만큼 복제되는 형식만 있고,
  실제 값은 전부 미정).
- **최대 레벨: 5**(슬롯 절과 동일).
- 레벨업 시 플레이어가 성장 방향을 고르는가: **미정.**

## 진화

- **방식(미확정): 자동 진화.** 무기가 최대 레벨에 도달하면 자동으로 진화형으로 전환한다.
  별도 조건을 요구하지 않는다.
- 진화체는 원본보다 타격 범위가 넓다.
- 진화체 ↔ 원본 매핑, 진화 조건, 효과: **전부 미정.**
- 진화 후에도 원본이 선택지에 등장하는가: **미정.**
- 진화 방향을 보유 패시브로 분기시킬 것인가: **미정.**

## 타이밍 — 곡이 발사를 결정한다

### 채보에서 온다

발사 타이밍은 무기가 정하지 않는다. **곡의 해당 악기 트랙이 정한다.**

- 곡별로 악기 트랙의 연주 타이밍을 노트 데이터로 갖는다.
- 곡 소스는 SUNO AI로 만든 곡의 stem이다. **MIDI가 없다.**
- 그래서 노트는 **stem 오디오 분석(온셋 검출)으로 추출**하고 손으로 보정한다.
  전곡·전악기를 손으로 찍는 것은 유지되지 않는다.
- 저장 단위는 **박 인덱스**(마디·박·서브박)다. 초가 아니다.
  `BpmClock`이 박 인덱스로 돌고 `WeaponHandler`가 서브비트 틱을 흘리므로 기존 경로에 그대로 얹힌다.
  전제: 채보 추출 단계에서 곡의 BPM을 확정하고 노트를 거기에 스냅시킨다.

### 레벨이 리듬을 바꾸지 않는다

무기를 강화해도 **연주 노트는 곡 그대로**다. 세기(데미지 등)만 강해진다.
레벨에 따라 서브 노트를 개방하거나 트랙을 갈아끼우는 방식은 채택하지 않았다.

### 곡과 세트리스트

- **한 판 = 한 스테이지 = 곡 4회 재생.** 제작 상 스테이지당 1곡을 4번 반복 재생하는 것을
  기본으로 하고, 여유가 되면 4곡을 모두 다르게 만든다.
- 곡이 바뀌면(또는 회차가 바뀌면) 채보가 바뀌므로 무기의 연주 패턴도 바뀐다. 이게 긴 스테이지의 변주다.
- **세트리스트는 같은 악기 구성의 곡들로 짠다.** 곡이 바뀌었는데 내 무기의 악기가 없어
  침묵하는 상황을 곡 선정 단계에서 막는다.
- 곡 전환 시 `BpmClock`의 BPM·앵커를 갈아끼우는 처리가 필요하다. (미구현)

## 구현 축 매핑 — 재검토 필요

기존 구현은 발사 형태를 4축(`ProjectileWeapon`/`AreaWeapon`(지속 0)/`AreaWeapon`(지속 >0)/`BurstTiming`)
으로 나눴다. 위 "형태별 분포"의 5축(자기 중심/투사체/반사/빔/궤도)과 더는 1:1로 맞지 않는다 —
특히 **반사(탐)·빔(신스의 지속 빔)·궤도(어쿠스틱 기타)는 지금 구현에 대응하는 클래스가 없다.**
구현 격차이며, 클래스 설계는 별도 작업으로 다시 짜야 한다(→ `architecture.md`).

  이 게임의 전제가 성립하지 않는다.
- **곡 전환 처리** — 세트리스트에서 다음 곡·회차로 넘어갈 때의 클록·채보 교체.

  악기별 색·모양은 발사 형태가 굳은 뒤에 정한다.
- **시퀀서 UI** — 표시/비표시 정보, 최대 트랙 수, 상한 초과 시 처리.
