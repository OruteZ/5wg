feat/stage-play

스테이지 플레이 루프

이번 브랜치에서 추가한 코드가 어떻게 돌아가는지에 대한 설명서. 한 줄씩 읽지 않아도 구조가 잡히도록, "누가 무엇을 결정하는가"를 중심으로 정리했다.

0. 이 슬라이스가 하는 일

이 게임은 리듬 기반 자동공격 2D 게임이다. 플레이어는 이동만 하고, 무기는 박자에 맞춰 알아서 발사된다. 적은 사방에서 스폰되어 플레이어를 쫓아온다.

브랜치 전까지는 끝이 없었다. 씬을 열면 무한히 돌기만 했고, 플레이어를 죽일 수단조차 코드에 없었다. 이번에 붙인 것은 딱 네 가지다.

시작 — 스테이지가 "이제 시작"이라고 선언하고 박자·스폰·발사를 연다.
클리어 — 정해진 마디를 버티면 끝난다. (임시 규칙)
사망 — 적에게 맞아 체력이 0이 되면 끝난다.
흐름 — 메뉴에서 시작해 결과를 보고 다시 돌아온다.

1. 시스템 지도

핵심은 네 덩어리가 서로의 내부를 모른다는 것이다. 화살표는 "이쪽이 저쪽을 안다"는 뜻이다.

왜 이렇게 나눴나. 지금의 클리어 조건("8마디 버티기")은 임시다. 나중에 실제 곡을 소유하는 음악 오케스트레이터로 바뀐다. 그때 StageDirector를 뜯어야 한다면 설계가 잘못된 것이다. 그래서 디렉터는 끝났다는 사실만 받고, 그 판단은 바깥에 뒀다.

2. 스테이지가 시작될 때

씬을 열면 아래 순서로 흐른다. 중요한 건 디렉터가 선언하기 전까지 아무것도 돌지 않는다는 점이다.

  1. Awake — 참조를 찾고, 전부 끈다. 인스펙터에 연결된 클록·스포너·플레이어를 잡는다. 비어 있으면 씬에서 찾는다. 그리고 스폰·발사·입력을 일단 모두 꺼둔다.
  2. Start — 종료 소스를 묶는다. 각 소스에 디렉터 자신을 넘긴다. 이때 PlayerDeathEndSource가 플레이어의 사망 이벤트를 구독한다. Awake가 아니라 Start인 이유는, 상대 컴포넌트의 초기화가 끝난 뒤여야 구독이 안전하기 때문이다.
  3. Begin() — 문을 연다. 상태를 Playing으로 바꾸고, 클록을 Stop() 후 Play() 해서 지금 이 순간을 비트 0으로 다시 앵커한다. 그 다음 스폰·발사·입력을 열고, 소스들에게 "계측 시작"을 알린다.
// StageDirector.Begin() — 실제 코드
ChangeState(StageState.Playing);

if (_clock != null)
{
    _clock.Stop();
    _clock.Play();     // 스테이지 시작 = 비트 0
}

SetCombatActive(true); // 스폰 · 발사 · 입력을 한꺼번에

foreach (StageEndSource source in _endSources)
    source.OnStageBegin();

3. 스테이지가 끝날 때

끝을 알리는 방법은 딱 두 개의 메서드다. 클리어든 사망이든 같은 문으로 들어온다.

시간을 멈추지 않는다. 보통 게임은 Time.timeScale = 0으로 정지시킨다. 이 게임은 안 된다. 박자 클록이 AudioSettings.dspTime(오디오 하드웨어 시계) 기준이라 timeScale을 0으로 해도 박은 계속 가고, 오히려 화면과 비트가 어긋난다. 그래서 축별로 개별 차단한다 — 스폰 끄기, 발사 끄기, 입력 끄기.

4. 플레이어는 어떻게 죽는가

이번 브랜치 전까지 플레이어를 때리는 주체가 하나도 없었다. TakeDamage를 부르는 건 아군 투사체뿐이었다. 그래서 적에게 접촉 공격을 붙였다.

충돌 판정이 조금 특이해서 짚고 간다.

상황결과이유
적 ↔ 플레이어데미지 발생플레이어 콜라이더가 트리거라 겹칠 때 OnTrigger가 온다
적 ↔ 적무시둘 다 트리거가 아니라 이 경로로 오지 않는다
적 ↔ 아군 투사체무시투사체는 IDamageable이 아니라 걸러진다
적이 겹친 채 머무름재타격 간격마다 반복Enter가 다시 오지 않으므로 Stay도 받는다

적은 상대가 누구인지 모른다. IDamageable이기만 하면 때린다. 덕분에 나중에 파괴 가능한 오브젝트가 생겨도 적 코드를 고칠 필요가 없다.

5. 씬은 어떻게 오가는가

MainMenu ──START──▶ Stage01 ──클리어/사망──▶ 결과 오버레이
    ▲                    ▲                        │
    │                    └────── RETRY ───────────┤
    └────────────────── MENU ─────────────────────┘

재도전은 상태를 되돌리지 않고 씬을 통째로 다시 로드한다. 체력·풀·인벤토리를 하나씩 되감는 리셋 경로를 만들면 빠뜨리는 게 반드시 생기기 때문이다. 씬 이름 문자열은 GameFlow 한 곳에만 있다. UI는 씬 이름을 모른다.

6. 바꾸고 싶을 때 어디를 건드리나

하고 싶은 것건드릴 곳안 건드려도 되는 곳
클리어 조건을 곡 기반으로 교체 StageEndSource를 상속한 새 컴포넌트를 만들어 씬에서 갈아끼운다 디렉터, UI, 스포너, 무기
클리어까지의 마디 수 조정 씬의 BeatTimelineEndSource 인스펙터 코드 전부
접촉 데미지 · 재타격 간격 Enemy 프리팹 인스펙터 코드 전부
상점·컷신처럼 전투만 잠깐 멈춤 WeaponHandler.AttackEnabled 또는 IFireGate 등록 디렉터 상태 (건드리면 안 된다)
HUD에 위젯 추가 StageHud + 씬의 Canvas 게임플레이 코드 전부

public sealed class MusicOrchestrator : StageEndSource

    // HUD가 이 값을 그대로 진행도 바에 그린다
    public override float Progress => _playedBars / (float)_totalBars;

    public override void OnStageBegin() { /* 곡 재생 */ }
    public override void OnStageEnd()   { /* 곡 정지 */ }

디렉터의 종료 소스 배열에 넣기만 하면 된다. 비워두면 씬 전체에서 자동으로 수집한다. 여러 개를 동시에 두면 먼저 끝을 알린 쪽이 이긴다(OR 조건).

7. 지금의 한계

박은 프레임과 무관하게 간다. 클록이 오디오 시계 기준이라 창이 비활성이거나 긴 히치가 나면 프레임이 멈춘 동안에도 박이 흐른다. 검증 중 실제로 목격했다 — Unity 창이 비활성인 사이 박만 흘러 스테이지가 즉시 클리어됐다. 빌드에서 알트탭하면 드러난다.

클리어 조건은 임시다. "8마디 버티기"는 기획 확정 전 자리 채우기다. 마디 수 필드도 그때 사라진다.

밸런스는 미조정. 가만히 서 있으면 클리어(120BPM 8마디 = 16초) 전에 죽는다. 이동으로 카이팅하는 걸 전제한 수치다.

범위 밖. 카운트다운, 일시정지, 성장(무기 획득·레벨업) UI는 이번 슬라이스에 없다.
